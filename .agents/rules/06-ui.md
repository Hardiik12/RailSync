# RailSync — UI Architecture Rule

## 1. Purpose

This rule defines the mandatory frontend architecture, visual direction, page structure, interaction patterns, and visualization requirements for RailSync.

The frontend must present RailSync as:

> A modern railway operations simulation and DSA analytics control center.

The UI must make the DSA algorithms understandable and demonstrable.

Visual quality is important, but visual effects must never replace algorithmic functionality.

---

# 2. Approved Frontend Stack

Use:

- React
- Vite
- JavaScript / JSX
- Tailwind CSS
- React Router
- Framer Motion

Do not replace the frontend stack without explicit approval.

Do not introduce another UI framework simply for styling convenience.

---

# 3. UI Design Direction

The visual language should be:

- dark
- modern
- technical
- data-dense
- clean
- railway-oriented
- futuristic but restrained
- professional
- responsive

The interface should feel like a railway operations and analytics platform rather than a generic SaaS dashboard.

---

# 4. Visual Style

Use:

- dark surfaces
- strong visual hierarchy
- subtle borders
- restrained gradients
- clear typography
- compact data cards
- tables where data density matters
- charts where trends matter
- graphs where graph algorithms matter
- controlled animation
- railway-inspired icons and visual language

Avoid:

- excessive neon
- excessive glow
- excessive gradients
- huge decorative elements
- unnecessary 3D effects
- excessive glassmorphism
- fake AI interfaces
- random animated backgrounds
- distracting particles
- excessive red
- generic template appearance

The interface should remain readable first.
