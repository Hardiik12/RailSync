# RailSync — Git and Version Control Rule

## 1. Purpose

This rule defines Git workflow, branch strategy, commit conventions, change isolation, and repository hygiene for RailSync.

Git history must make the development process understandable.

Every significant change should be:

- isolated
- explainable
- reviewable
- testable
- traceable to a project requirement
